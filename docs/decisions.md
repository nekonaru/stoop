# Design decisions

## 2026-11-15: Project kind and packaging

- Stoop is a general-kind project: a command line tool and daemon, distributed through the repository (no registry publishing in v0.1.0).
- Ruby 3.2+, gem set fixed by the PRD: nokogiri, faraday, sqlite3, thor, rufus-scheduler, rspec, webmock, rubocop.
- Telegram notifications are delivered with plain HTTP (faraday), no bot framework, to keep the dependency surface small.
- Secrets only from environment variables (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`). Nothing secret is logged or committed; `.env` is gitignored and `.env.example` documents the variables.

## 2026-11-15: Release pipeline

- Branch, PR, CI (rubocop, rspec, coverage gate for price parser and rules, secret scan), squash merge, then a signed tag `vX.Y.Z` once CI is green on `main`.
- Release notes are bilingual (English first, Bahasa Indonesia second) following the release template, with `CHANGELOG.md` and `CHANGELOG.id.md` kept in sync.
- License is MIT.

## 2026-11-15: Brand assets

- The mark is a descending staircase with a red dot (price drop), drawn from the provided artwork.
- `assets/stoop-mark.svg` and `assets/stoop-mark-dark.svg` are vector masters built from measured geometry; `assets/stoop-mark.png` and `assets/stoop-mark-dark.png` are renders used in the README header and assets.
- The full lockups (`assets/stoop-logo-light.png`, `assets/stoop-logo-dark.png`) are cropped from the provided image and keep the original composition.

## 2026-11-16: Off-by-one in previous price

- Bug found in testing: the tracker asked the database for the previous price point before inserting the new one, but the query returns the point before the latest, so it skipped the point that was actually previous. Fixed by reading the latest point before recording the new one. A regression spec covers this.

## 2026-11-16: robots.txt handling

- Conservative subset of RFC 9309: groups separated by blank lines (or a user-agent line after rules), the most specific matching group wins, longest Allow/Disallow prefix decides within the group, Allow wins ties. Absent or unreadable robots.txt allows the fetch. Specific rules for our user agent are honored, wildcard groups otherwise.

## 2026-11-16: Notification dedup and cooldown

- Never notify twice for the exact same price (tracked as `last_notified_price`). A restock event bypasses the price dedup. The 12 hour cooldown always applies, even when the price changed.
- Three consecutive check failures (configurable via `stale_after_failures`) mark a product stale; one Telegram alert is sent per stale episode.

## 2026-11-16: http and rate limiting

- 5xx and network errors retry up to 3 times with exponential backoff (1s, 2s, 4s); 4xx responses do not retry. Per-host requests are spaced 5 seconds apart by default; the minimum check interval in the daemon is 30 minutes.
- Redirects are not followed implicitly; a non-2xx final status is treated as an error and surfaced to the user.

## 2026-11-16: CSV and dependencies

- CSV export is generated by hand (RFC 4180 escaping) to avoid adding a gem for one feature; the gem set stays the one from the PRD.
- Output formatting helpers live in `Stoop::Format`; the CLI composes them. Table output, rupiah formatting and percent change are shared there.

## 2026-11-16: CI notes

- GitHub Actions CI runs rubocop, rspec and a stdlib-coverage gate (parser and rules files must stay above 80%) on Ubuntu, Windows and macOS against Ruby 3.2 to 3.4, plus a gitleaks secret scan.
- The workflow configures a gem source mirror for reliability of gem downloads; gems install from the mirror, but CI remains the source of truth for the lockfile.
